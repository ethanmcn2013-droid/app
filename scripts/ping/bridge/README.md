# Disposable typed/input execution bridge

This disposable PP013/014 construction connects real operation binding and synthetic input-finality descriptors to the actual injected Ping service, original-intent receipt recovery and an authorized local row/schedule projection. There is no App route, ambient database/session import, microphone, provider request, customer environment or production migration. Agent implementation choices are recommendations approved under delegation, not founder-specific picks.

`createPingProofBridge(capture, ports)` takes application-owned immutable capture, actual execute/plan-bound receipt/local reader ports and a monotonic clock. `stageTyped(proposal, completeSeal)` accepts an explicit labelled operation proposal through the strict binder; it is not a free-form instruction parser. `step(event)` drives the existing bounded synthetic input reducer. Complete synthetic tail/final-before-ACK/ACK/interpretation/dispatch events are tested through the actual file-backed service. Descriptors remain descriptions: `invoke()` owns the one actual invocation latch and rechecks cancellation/context and the 10-second bound-to-invocation guard before setting that latch and calling the executor.

The runner refuses external receipt events. Successful actual executor results and original-intent lookups must pass bounded receipt identity/effect/count validation. It keeps the frozen original command/context/key until outcome reconciliation. The exact key is sensitive internal metadata; it is neither a cryptographic hash nor authentication token and is never model input or a product log. The service's additive `getReceiptForCommand` reuses strict command/context/finality checks and its existing immutable SHA256 plan identity inside a READ transaction with current membership/capability/deletion fences. It never opens a write transaction, calls execute or allocates a replacement identity. Existing `execute` and `getReceipt` behavior is preserved.

`not_invoked` means this runner made zero executor calls; an already emitted dispatch descriptor can still be cancelled with actual calls 0. `unresolved` means an invocation began and effects are unknown/null. Cancellation, timeout, dropped response, generic service errors, absence or denial do not establish rollback or zero committed effects. `committed` requires an actual valid completion or authorized original-intent receipt. Receipt no_changes is a committed no-op. Post-invocation cancellation cannot undo DB work; no automatic executor retry or new UUID is available.

Manual `recover(actionToken)` is read-only with 3 reads/window at offsets 0/500/2000 ms,10-second windows,8 lifetime windows and bounded token dedupe. A reused token cannot start another window. Reads never overlap; an unresolved physical port continues occupying the read lane until it settles. A result arriving at/after its deadline is counted as failed and cannot confirm that window; a fresh bounded manual window can begin after settlement. This proof deliberately does not invent transport abortion, durable reload recovery or global actor ownership. Its synthetic reducer state remains a descriptor/control-flow diagnostic; the runner's actual knowledge is reported separately. Reducer-emitted receipt-read descriptors and runner-issued manual port reads are separate counters, not assumed one-to-one transport evidence.

`refresh()` performs a new authorized local projection after known commit, capped at 3 lifetime attempts with a10-second completion guard. These disposable delegated guards are not product availability promises. Stale/cancel/failure wipes view rows while preserving original receipt truth. `createProofReadback` checks current owner/member role, canonical Project capability and actor/owner/Project deletion fences in the SAME queued READ transaction as task selection. It reads at most 10 receipt task IDs in the explicit Project, top-level/unarchived. Actual libSQL numeric driver rows flow through Drizzle schema decoding, canonical `rowToTask` and actual `taskToSchedule`; literal JSON/date/null/comment/subtask tests demonstrate this compatibility rather than fabricating a client Task. A driver Client type adaptation is limited to this execute-only select path; it never calls a nested Drizzle transaction or opens a second connection. Remote adapter construction is refused by this fixture reader.

Current relevant post-state compares the immutable selected preimage plus intended self assignment/date/status effects, preserved collaborators/start/duration/board claim and canonical configured completion semantics. Historical receipt remains committed when later current state diverges, is denied, is missing, or cannot refresh. Partial/moved/archived/foreign rows cannot silently confirm. A stale/cancelled view does not receive projection rows. Description, priority, tags, unrelated rows and creation facts are additionally asserted through literal independent store observations; this does not establish a universal full-row revision or atomic browser snapshot. Due clearing can leave a separately Planning-Period-anchored range. Full V1 user timezones/custom operations and broader edit telemetry/invalidation parity stay open.

The local reader is a bounded receipt-target projection. It is not ambient `getTasks`/`getTasksAction`, production ordering/cap behavior, server-action revalidation, event emission, TasksProvider hydration, SSE, mounted Hybrid or visible browser completion. These require the later authenticated isolated floor and actual current-control comparison. No PP015/G1/G2/provider/release gate follows from this packet.

Counters measure actual runner port invocations, receipt/readback outcomes, fixed-tag adapter transaction attempts/completions/failures and executed callback SQL statements. Adapter transaction-control statements, fixture migrations/seeding and independent oracle SQL are excluded from callback-statement counts. One execute call can contain a READ plus WRITE transaction; a logical no-op still creates a receipt. Attempted statements and failed transactions are not committed effects. Oracle SQL runs only after active transactions settle and does not contaminate runner timings/counters.

Owning tests use factory-created marked synthetic file-backed databases with FK ON, real canonical capture entitlement/issuance when enabled and one queued local adapter. Sponsor capture creates one intent per created task and one actor/epoch subject row via canonical upsert. Clients close in finally. No arbitrary database path or environment-copy interface is added; safe cleanup follows the existing proof-fixture temp-root/marker restrictions. The known installed Windows libSQL same-process contention/poisoned-writer limitation remains: this bridge does not broaden the adapter or promise new writes recover by retrying. Read recovery can remain useful while writer recovery is a separate proof.

Run `pnpm test:ping-bridge`; it is a blocking step of `pnpm test`. Independent corpus tests belong to a later exclusive writer handoff; reserved screening instructions remain unopened.

Most fault tests use labelled synthetic clock/barrier times. The one/ten compound tests additionally report actual monotonic fixture-open invocation→authorized local projection intervals, with n=1 each and driver/import already initialized. These exclude fixture setup, instruction interpretation, speech, human Finish delay, current bulk controls, browser/network/hydration and verification/repair effort. They are neither stable p95 estimates nor voice/browser latency. Unknown/failed/stale projection has no completion interval. Exact revision/runtime/check receipts and receiving review are required before this finite packet is accepted.
