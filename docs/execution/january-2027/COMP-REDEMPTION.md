# Atomic comp redemption — 4 September 2026

New redemption commits code capacity, the project-bound entitlement, venue starter tasks/activities, template retry receipt and project metadata in one immediate writer transaction. Failed insert, task activity, receipt or metadata writes roll everything back. Retrying the same actor/code finds the original stored grant/project and preserves its term and subsequent task edits or deletions. Lock contention retries a bounded number of fresh transactions; uncertain network acknowledgements require replay of the same code.

Identity and the existing attempt budget run before lookup. The transaction checks membership, edit capability, archive, account erasure and project deletion. Code expiry prevents new claims; replay never revives expired or epoch-zero revoked access. The result link carries the stored project rather than relying on the active cookie. Error telemetry and the action response contain a fixed retry message, without raw SQL parameters or a bearer code.

Verification uses disposable SQLite, synthetic users and codes. Twelve new integration cases cover successful 18-task seeding, four injected write failures with retry, response loss/project switching, removed/foreign/archived actors, expiry/revocation, independent-connection contention, exhausted capacity, and both deletion fences before and after claim. The existing template suite passed 17 cases. Shared-term and code security contracts passed 35 cases after tracing the new delegation boundary. Full typecheck and focused lint passed before the final two fence cases; receiving CI must cover the exact committed tree.

Historical partial grants are not repaired by assumption. An existing entitlement with missing starter evidence may represent an old failure or deliberate user deletion. Replay preserves it; commercial operators must reconcile known failed fulfilment against provenance rather than automatically reseeding. Duplicate historical grants fail closed. This does not establish settled payment, a meaningful couple action, live provider behaviour, wedding-date updates, production rate limiting, or final rendered experience acceptance.
