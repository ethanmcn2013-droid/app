The sequence

Nine packages, dependency-ordered

Two of them are not about Drive at all, and both come first. The order is load-bearing: each package de-risks the next.

  • WP-0

    Fix the floor

    blocks everything

    The Signal-native upload path is the fallback this whole design leans on, and right now the product itself says it does not work. Establish whether the storage token is provisioned, make the four contradictory file-size numbers agree, and make the settings copy true.

    Done when  a real 5 MB PDF uploads and downloads again in production, and settings tells the truth.

  • WP-1

    Spike the Drive chain

    throwaway branch

    Two real Google accounts, seven steps: connect, create the folder, share it, upload from a browser, confirm the second account opens the file with no request-access, revoke, confirm access is lost — and confirm the parent folder was never visible. Publish the consent screen the same day, or Google's seven-day token expiry will look like our bug for a week.

    Done when  SPIKE-FINDINGS.md answers all seven with observed behaviour.

  • WP-2

    Secrets substrate

    There is no cryptography anywhere in this repository today. Build encrypted storage with key versioning before there is a refresh token to put in it — not after.

    Done when  no plaintext token can reach the database, the logs, or Sentry.

  • WP-3

    Schema

    migration 0028

    Three new tables and four additive columns. In this repository a migration is a ledger entry, a reviewed receipt and a journal entry as well as SQL — and the receipt stays marked not authorized for production until you say otherwise.

    Done when  pnpm db:contract passes and a second migrate run is a no-op.

  • WP-4

    The connection

    Connect, disconnect, reconnect. One scope, pinned by a test. Signed single-use handshake. Account deletion revokes at Google in the order the Notes module already established.

    Done when  reconnecting a different Google account is detected rather than silently adopted.

  • WP-5

    Folder and sharing

    security-critical

    One folder per board, shared with exactly that board's members, wired to the four places membership changes. Every grant path calls one guard function that refuses before the API call: never the parent folder, never another board's folder, never anything but a named user.

    Done when  a second account opens the board's files with no request-access step, loses them on removal, and never sees the parent folder.

  • WP-6

    Upload

    the capability win

    Bytes go browser to Google. We mint the session; the token never leaves the server; the client's claimed file id is verified against our own stamp and the board's folder before it is believed. One decision — stamping each upload with a private id — removes the duplicate-file problem entirely.

    Done when  a 400 MB file attaches, and killing the browser mid-upload then retrying produces one file, not two.

  • WP-7

    Surfaces

    It should feel like nothing changed, except that bigger files work. The attach control keeps its shape. Settings gains Connections. And the board gains “Who can open this board's files”, read live from Drive rather than from our own records.

    Done when  the plain-language and experience-registry gates both pass, with evidence at all four screen sizes.

  • WP-8

    Resilience and launch

    The invisible half that decides whether this is sellable: the repair pass for failed revocations, the storage-owner handover, and the privacy wording. Plus the Signal HQ records the repo contract requires.

    Done when  a removed member cannot retain access through a failed revocation, and the owner can see that is true.

Non-negotiable

Ten rules, each one enforced by a test

These are what turn the safety story from a promise into something a build can fail on. The plan requires code enforcement and a contract test for every one.

Scope and reach

  • 1The only scope ever requested is the narrow one. Widening it must fail the build.
  • 2Never share the Signal Studio parent folder — that would expose every board at once.
  • 3Named users only. Never “anyone with the link”, never a whole domain.
  • 4A grant only ever targets the folder recorded on that board's own row.
  • 5Share-link guests are never granted anything in Drive.

Data and trust

  • 6Signal Studio never deletes someone's Drive file as a side effect of tidying a task.
  • 7Access tokens are never stored. Refresh tokens are encrypted.
  • 8The caller's permission is proved on the object's own board before any Google call.
  • 9A file id from the browser is never evidence — verify it carries our stamp and sits in the right folder.
  • 10Demo mode never reaches Google or the real database.

Your desk

Five things the session will bring to you

The plan tells it not to decide these alone. Two are worth thinking about before it asks.

  • ·Is the storage token provisioned in production? This is question one, and it blocks WP-0. Settings currently tells every customer that uploads are not active — either that is true, or the copy is stale. Worth knowing before the session starts.
  • ·Do members get edit or view-only access in Drive? The plan proposes edit, because editing a shared Sheet in place is much of why putting files in Drive is worth doing. Reversible, but people will notice.
  • ·When may migration 0028 run against production? The receipt stays marked unauthorized until you say so — matching how the last migration was handled.
  • ·Which file-size number becomes the truth in WP-0, given four places currently disagree.
  • ·The privacy wording. Files will sit in a member's personal Drive; that is a real change to what you tell customers, and it changes what account deletion can promise.
One thing the plan deliberately holds back

Letting people attach files they already have in Drive — the picker — is genuinely valuable and entirely additive. It is deferred only because it needs a second Google component and would delay the capability you actually asked for. It is the obvious next package once this ships, and the schema already has room for it.

The finish line

What “done” means

  • ✓All ten rules enforced in code and proved by a contract test.
  • ✓Every gate green: lint, types, the full test suite, the migration contract, plain-language, and the experience registry.
  • ✓Two real Google accounts walk the whole lifecycle — connect, attach, second member opens, member removed, access lost.
  • ✓Signal Studio's own storage still works with Drive disconnected. The feature can be switched off at any moment without a customer losing a file.
  • ✓STATUS.md reflects reality, and the dispatch entry is written.
