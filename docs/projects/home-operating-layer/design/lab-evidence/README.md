# Home operating layer · the four directions, rendered

Visual evidence for the founder's visual-direction selection. Four directions,
ten captures each, two viewports, two crops. 160 PNGs.

Generated by `scripts/home-layer/render-directions.mjs`. Re-run with:

```
node scripts/home-layer/render-directions.mjs
```

## Why these were rendered offline, and what that does not cost

The lab cannot be reached over HTTP on a development machine, and that is
correct rather than broken. `src/lib/home-layer/lab/policy.ts` refuses in this
order — flag-off, seed-data-posture, not-authenticated, not-a-reviewer, granted
— and every local server runs in a seed-data access posture, so the route
returns a real 404. A live 200 needs production posture, real Clerk keys and a
signed-in reviewer.

Nothing here weakens that. The capture script makes no request, so it never asks
the guard anything. It drives the same components the route drives, in process:

- Props are assembled through the real lab shell — `parseLabUrl` then
  `assembleCandidateProps` then `withCandidateVariant` — in the same order
  `src/app/lab/home-operating-layer/page.tsx` uses. `assembleCandidateProps`
  takes a `LabViewState`, which carries no `v`, so all four directions are
  handed one frozen object built from one input. The fairness guarantee is
  enforced by the type and is not bypassed here.
- The four `candidates/*/candidate.tsx` components are the real ones, rendered
  with `react-dom/server`.
- No candidate, no fixture, no shell file and no guard was modified to produce
  these.

## Is the styling faithful?

**Yes.** Not approximate — the same bytes the build would ship.

- The four candidate stylesheets (`editorial.css`, `rail.css`,
  `reading-index.css`, `desk.css`) are plain CSS: no `@import`, no `@apply`, no
  `@theme`, no nesting. They are inlined verbatim, so what the page has IS what
  the build emits.
- The candidates use **no Tailwind utility classes at all**. Every class is
  prefixed `ed-`, `rl-`, `ri-` or `dk-`. There is no utility layer for the
  captures to be missing.
- `src/app/globals.css` is compiled by the same `@tailwindcss/postcss` plugin
  `postcss.config.mjs` names, which resolves `@import "tailwindcss"`,
  `src/ds/tokens.css`, `src/ds/theme-overrides.css` and `src/ds/tailwind.css`.
  So Preflight, the vendored design tokens and the utilities the root layout
  uses (`h-full`, `antialiased`, `min-h-full`, `flex`, `flex-col`) are all
  present. The script exits non-zero rather than writing a page whose compiled
  globals lack `--paper`.
- Geist and Geist Mono are embedded as data URIs from the `geist` package.
  `tokens.css` declares `--font-sans: var(--font-geist-sans, "Geist"), "Geist",
  …`, so with next/font absent the vendored fallback chain resolves to the real
  face. The type in these captures is Geist, not a system stand-in.

Three honest limits, none of which changes what a direction looks like:

1. **No client JavaScript ran.** These are the server-rendered documents, which
   is exactly what a real reader sees before hydration. Editorial is the only
   direction with any client code (`interaction.tsx`); its transitions — mark
   read, snooze, approve, recover — are not exercised here.
2. **Light theme only.** Every capture is `theme=light`. Dark was not in the
   matrix.
3. **No row is selected.** Every capture uses the arrival state, with no
   `?item=` or `?event=`. See "What these captures do not show" below.

## Reading the filenames

```
<candidate>__<mode>__<scenario>__<viewport>.png        full page
<candidate>__<mode>__<scenario>__<viewport>__fold.png  what is on screen on arrival
```

Candidates are `editorial`, `rail`, `index`, `desk` — variants 1 to 4, picker
order. Viewports are `1440x960` and `390x844`.

The `.html` sources sit beside the PNGs and are git-ignored: each one carries
its own inlined stylesheet and two embedded fonts, so the set is about 16 MB.
Re-run the script to rebuild them; open one in a browser to inspect a direction
at any width.

## What the renders actually show

These describe the pixels, not the intent.

### 1 · Editorial

A centred single column on white, roughly 740px of measure, with a thin
Signal Studio masthead and a mode row above it. The page reads as a broadsheet:
a small caps dateline (`READ AT 08:40 ON THURSDAY 16 JULY.`), a large tight
headline set in Geist ("What is asking for you now."), then a standfirst
sentence, then numbered entries — `01`, `02`, `03` in a grey monospaced margin —
whose titles are underlined links. Section rules are hairlines under a bold
heading, with one indigo rule under Today's signal as the only colour on the
page apart from red overdue text. Every page ends in a three-column colophon,
"HOW THIS PAGE WAS READ", which is where the accounting sentence, the actor, the
Active Project and the unsupported-source notes are parked. The quiet world
compresses to a single screen: headline, one honest sentence, colophon, nothing
else. It is the most restrained of the four and the most typographic; at 1440 it
uses only the middle 840px of the window and leaves the rest as margin.

### 2 · Rail

A fixed 240px left sidebar on a very pale tint, holding the wordmark, the four
Home modes with the Inbox badge, the three products, the Read Scope control,
the as-of line and the actor. Content sits in a measure to the right of it. This
is the only direction whose navigation is persistently visible, and the only one
where the mode you are in is marked by a filled active row rather than by an
underline. The content itself is the plainest of the four — headline, standfirst,
underlined section headings, rows with title, reason, then a metadata line of
provenance, lateness and idle time — and it is also the shortest: Today on the
signature world is 1565px against 2383–2685 for the other three. The trade shows
at 1440: with a 240px rail and a capped measure, the right ~450px of the window
is empty. On mobile the rail unstacks to the top, so a reader on a phone scrolls
past the whole navigation block — wordmark, four modes, three products, scope,
as-of, actor — before reaching the headline.

### 3 · Index

The widest of the four, using nearly the full 1440. It opens with a leader-dot
contents table — `01 Today ……… Read`, `02 Inbox ……… Partly read` — which doubles
as the mode navigation and as a per-mode coverage report, so the state of a mode
you are not in is legible from the mode you are in. Below it the headline, then a
"CHANGE WHAT HOME READS" field styled as a form control, then the body in a
two-column layout with a sticky "ON THIS PAGE" rail on the right listing the four
Today sections. Rows are numbered in a monospaced margin and provenance is set in
monospace too, which gives the page a documentary, records-first texture. Coverage
problems get their own bordered block above the content, headed "WHAT LIMITED
THIS READ", with a red rule. It is the most information-dense direction and the
tallest — Analytics runs to 4054px.

### 4 · Desk

The only direction that changes the canvas: `desk.css` warms `--paper` with a
`color-mix`, so the whole page sits on a warm off-white rather than the white of
the other three. The chrome is a three-tier header — products, then actor plus
Read Scope, then the mode tabs — and the mode tabs are a genuine tab row with an
indigo underline. The body is a spine: a vertical rule down the left with small
indigo squares marking each entry, which reads as a ledger or a docket. Where the
read is limited, Desk raises a tinted band immediately under the headline ("2
notes at the foot say what this read could not see") that links down to a "What
this read could not see" section at the foot, so the disclosure is announced at
the top and paid off at the bottom. Provenance and dates are separated by rules
into fielded metadata. It is the most product-like of the four and the only one
whose colour temperature differs from the design system's default paper.

## What these captures do not show

Read this before treating the set as complete.

- **Detail behaviour is absent from all four.** Every capture is the arrival
  state, with no `?item=` or `?event=` in the URL. Detail behaviour — panel,
  page, in-place disclosure — is one of the axes the four directions are meant to
  differ on, and none of it is visible here. Editorial's row actions, for one,
  render only inside an opened event, so its Inbox looks action-free in these
  PNGs and is not.
- **Motion is not captured.** Each shot was taken 700ms after fonts settled, so
  entrance animations are on their final frame. The signature moment each
  direction was asked for cannot be judged from a still.
- **The `new_user` world reads as a failure, in all four directions.** Today
  shows "Home could not read any project at this scope" and, in Desk, a "COULD
  NOT BE READ" band. That comes from the shell's scope resolution, not from any
  one direction, so it is not a point of comparison between them — but it is
  worth someone deciding whether a person's first ever screen should be phrased
  as a read that failed.
- **Dark theme is untested.** No capture carries `theme=dark`.
