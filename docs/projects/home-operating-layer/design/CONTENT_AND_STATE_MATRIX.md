# Content and state matrix — the Home fixture universe

**Wave 2 · authored 2026-08-12 · base `origin/main` @ `c592e83`, branch `feat/home-operating-layer`**

What every Home surface renders, in every scenario, with the number it renders and where that
number comes from. This is the document a lab agent draws from and a director reviews against.

The code is `src/lib/home-layer/fixtures/**`. The machine-readable form of everything below is
`experience/home-operating-layer/fixtures/manifest.json`, regenerated by a script and pinned by a
test, so a moved number appears in a pull-request diff rather than in a screenshot nobody compared.

---

## 1. The one rule this universe exists to enforce

> Unknown stays unknown. Missing, incomplete, unsupported, stale, permission-limited, failed or
> insufficient-history data may never render as zero, healthy, complete, empty or all clear.
> **A quiet day and a broken provider must be visibly different.**

Two design consequences follow, and both are load-bearing.

**Every count is derived, never typed.** No number in the fixture is written by hand. `read`,
`shown`, `cappedOut`, `dismissed`, `cleared`, the badge, the group sizes, the claim values and the
ledger are all computed from the records by `src/lib/home-layer/fixtures/derive.ts` and the
per-mode derivations. A fixture that could assert "three items, two capped" without its own data
supporting it is a fixture that will eventually assert something false, and nobody will catch it,
because a plausible number is indistinguishable from a true one.

**A value that cannot be computed is `null`, and `null` renders the reason.** Not `0`, not a dash,
not an empty chart, not a greyed axis.

## 3. The frozen clock, and the two irregular days

| | Value |
|---|---|
| Today | `2026-07-16` |
| `asOf` | `2026-07-16T07:40:00.000Z` = 08:40 BST |
| Zone | `Europe/London` — BST in July, so a non-zero offset is exercised by default |
| Clocks back | 25 Oct 2026, 02:00 BST → 01:00 GMT. Local **01:30 happens twice**; the earlier is `00:30Z` |
| Clocks forward | 28 Mar 2027, 01:00 GMT → 02:00 BST. Local **01:30 never happens**; forward to `01:00Z` |

Both transitions are **re-measured with `Intl.DateTimeFormat` on every test run** rather than
trusted from the constants, so a tzdata update fails the suite instead of silently changing what
the `dst_boundary` scenario proves.

`dst_boundary` reads from its own pinned instant, `2026-10-24T20:15:00.000Z`, the evening before
the change — so "tomorrow" is a **25-hour local day** and any window computed as
`+ 7 * 24 * 60 * 60 * 1000` lands on the wrong date. `dst.test.ts` proves that concretely: the
Sunday-morning row reads as *today* under millisecond arithmetic and as *Next* under calendar
arithmetic.

Two rows deserve reading twice.

**`permission_changed` and `provider_failure` withhold the accounting entirely.** A source that
could not be read means a term of the identity cannot be computed, and §6 is explicit: the whole
accounting is withheld and the reason is named. It is never partially rendered and never guessed.

and nothing writes analytics snapshots (`Q8`). The honest sentence names what was read, what was
not read, and what is true. A surface that says "all clear" here is claiming to have looked at a
calendar it cannot see.

### Every URL

is a pure function of those parameters — so **reload cannot produce a different screen**, and
neither can a different machine. The capture matrix is **4 directions × 5 modes × 13 scenarios =
260 URLs**, all distinct, all listed in the manifest.

## 5. Per-mode content and state

### 5.1 Today

At most **three** ranked items, each able to say why it is there.

| Section | Cap | Implies completeness | Row origin |
|---|---|---|---|
| Today's signal | 3 | no | `due-soon` `crowded-week` `stuck-work` `blocked-too-long` `overload` `doing-empty` |
| Coming up | 4 | no | dated, open, `2 < daysOut ≤ 14`, crossed no rule |
| Needs review | 3 | no | engine lane `review`, plus `blocked-too-long` |
| Moving well | 3 | no | `just-shipped` `blocker-cleared` |

All eight triggers fire somewhere in the universe, and none fires by accident. `doing-empty`
needed its own candidate set, because it only fires with five or more assigned items in `next`
and **zero** in `in-flight` — a condition the signature world cannot produce, so it is not bent
into producing it.

In `owner_signature` the three ranked rows are an overdue item, an item due today, and a
**synthetic** `crowded-week` row. The synthetic is the important one for design: it is a *reading
of* three objects, it carries the refs it was read from, and it is never counted as an object in
its own right.

**Refused vocabulary.** Nine conditions forbid quiet, all-clear or reassuring language. No V1
world reaches `quiet.allowed === true`, because `Q7` always holds — there is no calendar producer
at this base. `determinism.test.ts` and `truthfulness.test.ts` assert that, so a direction that
finds a way to say "you're all caught up" fails a test rather than a review.

**`calendar-event` and `decision` render `unsupported`.** Never an empty section, never "nothing
scheduled", never `0`. The prohibited renderings are enumerated in the fixture so a scan can catch
them.

### 5.2 Inbox

Visibility (`new | read`) and disposition (`open | snoozed | acknowledged | cleared`) are
**independent**, and all **eight** cells are occupied by real events. The two that prove it:

- `new / cleared` — cleared without ever being read. Clearing is personal and touched no source
  work; the approval is still outstanding at source.
- `read / open` — read and still open. **Reading never resolves.**

**The badge counts `open`, not `new`.** Visibility is not an input. If reading emptied the badge,
reading would resolve, which is the thing the two axes exist to prevent.

An event contributes 1 only if: a state row exists, the **effective** disposition is open
(including a snooze whose resurface time has passed — a read-time predicate, no job runs),
the event is not withdrawn, the kind is one of the six, the Project is live and not archived, and
source visibility is `available` or `undetermined`.

**Three source-visibility states, not interchangeable.**

| State | Renders | In the badge |
|---|---|---|
| `available` | normally | yes |
| `unavailable` | a neutral "no longer available", **no stale content, no reason** | no |
| `undetermined` | named as undetermined — not gone, not empty | yes, and the count discloses it |

**Source visibility is per actor**, and the universe proves it: `home-cmt-0010` is `unavailable`
to Orla in `permission_changed` (her membership was revoked) and `available` to Dara in
`guest_limited` (he is still a member). Neither result may be used to render the other's row.

**Rows store identifiers and state only.** No title, no snippet, no display name, no email, no
avatar URL is on any event row — asserted structurally against the contract's own field list, and
again by scanning the serialised rows for every display word in the universe. Display is hydrated
live, after authorization, on every request.

**Action outcomes.** `committed` carries `sourceRevisionAfter`; `refused` carries a `refusalCode`
and **leaves the event open**; `undetermined` is a third outcome that settles to nothing and is not
a failure. `action_failure` uses the refused one: the optimistic UI rolls back visibly and offers
recovery. There is no success toast without a state transition.

**Snooze.** Three cases: an ordinary evening, the ambiguous autumn hour (resolves to the
**earlier** occurrence), and the spring gap (resolves **forward** to the first real instant). The
zone is an explicit argument in all three; there is no ambient default.

**Scale**: 50 events across 10 threads, so grouping and pagination are exercised rather than a
flat list of fifty rows.

### 5.3 My work

Exact `Waiting > Now > Next > Later` precedence, one row in exactly one group, and all **seven**
reason codes produced by real rows:

| Group | Reason | The row that produces it |
|---|---|---|
| Waiting | `blocked-by-dependency` | Ballyhoura marquee lighting, blocked by the generator |
| Waiting | `in-waiting-column` | Ballyhoura venue confirmation — in a column **renamed** "Waiting on the venue" |
| Now | `overdue` | Orchard kitchen numbers, 2 days past |
| Now | `due-today` | Orchard seating plan |
| Next | `within-seven-days` | Orchard car arrivals, at **T+7**, the inclusive edge |
| Later | `beyond-window` | Adare running order, at **T+8**, the first Later day |
| Later | `no-date` | Orchard thank-you wording |

**Waiting comes from structure, never from a display name.** Nora & Cian renamed the column to
"Waiting on the venue"; the key is still `waiting`, so nothing changed. That is the point of
keying on it.

**`waiting: "unknown"` is a real state.** Aisling & Tom deleted its Waiting column, so V1 has no
waiting signal for that Project. Its rows are grouped by date and the view discloses it. "No
waiting signal" and "not waiting" are different statements and stay different.

**Done resolves per Project.** Nora & Cian marks `signed-off` as done. A projection that hardcodes
`lane === "done"` measures that Project wrongly and silently, so the fixture carries the case.
Done rows are excluded by default and the exclusion is a **filter the reader can see and reverse**,
never an absence.

**`unverified` is never rendered as `denied`.** The Dromoland row carries
`complete: "unverified", reassign: "denied"` so a direction has to render three capability states,
not two.

**An unparsed due label is visibly undated**, never a guessed date: the row carries
`dueLabel: "before the rehearsal"`, `dueUnparsed: true`, `dueDate: null`.

**V1 coverage is Tasks-only, and pays for it with a literal receipt** in a permanent position:
*"This shows work assigned to you in Tasks. Notes and Timeline are not included yet."*

**Pagination** is a keyset cursor over a total order (`dueDate ASC nulls last`, `workspaceId`,
`taskId`). A cursor whose `today` differs from the current `today` is **rejected** with an explicit
`day-rolled-over` reason, never silently reused.

**Scale**: 60 responsibilities, spread across all four groups, one with a 160-character title so
row rhythm at 320 px is a composition problem the lab has to solve rather than avoid.

### 5.4 Analytics

Every claim declares seven things or does not render: definition, truth class, scope, window,
population, coverage, four times, history, permission, provenance, limitation, correction, value.

**Seven claims render in V1**: `open_work` (reported), `open_overdue_work` (reported),
`unowned_work` (reported), `work_completed` (observed), `open_work_age` (observed), `stalled_work`
(**inferred**, threshold stated inline as 7 days), `cross_product_milestone_risk` (**inferred**,
and explicitly one-legged — it can only under-count and is never rendered as "no risk").

`open_work` is the denominator for three of the others, so "3 of 24" quotes two derived numbers.

**Six claims are withheld**, each with the defect that withholds it and the condition that would
ship it: `blocked_work` (R2), `open_decisions` (R4), `milestone_movement` (R4),
`completion_pace_change` (R7), `follow_up_completion` (R8), `workload_distribution` (D-HA08).
None renders as `0`; the absence is named.

**One trend, or none.** `open_work` only, and only above **14 comparable daily snapshots**. Below
it: the words, the exact gap, the earliest possible date, and **no chart** — not empty, not flat,
not a single point, not a greyed axis. Twelve of the thirteen scenarios sit below the minimum,
because at this base nothing writes snapshots at all. `scale` is the one world that earns it.

**No accepted baseline exists anywhere in the repository**, for any metric. Every claim ships
`{ kind: "none" }` and renders the literal words **"No accepted baseline"** — not a dash, not
"n/a", not omission. Target, goal, quota, expected, should-be and on-track-to are baseline
language and appear nowhere.

**At most three ranked exceptions.** The fourth is not "see more"; it does not exist as a rendered
thing.

**A complete authorized Project ledger.** Every Project in the authorized set appears with its
state, including `unresolved`, `archived` and `empty`. `permission_changed` renders four rows for
four Projects, one of them unresolved and carrying **no name and no counts**. `scale` renders all
eighteen.

**Receipts replay.** `receiptFor` names every included and excluded record; `replayOpenWork`
recomputes the value from the receipt alone and must match byte for byte.

**The Project Lens changes neither axis.** Opening, changing or closing it leaves Home Read Scope
and Active Project untouched. An unauthorized lens does not open and the page underneath is
unchanged — proved by `permission_changed`, whose lens targets the revoked Project.

### 5.5 Full briefing

The **same engine, the same pass, the same `asOf`, the same version** — with the caps lifted.
`rankToday({ limit: "all" })` returns the same result object with a different limit. It is not a
second view model, which is what makes charter rule 9 checkable rather than aspirational.

## 6. Privacy — the sentinel

Every fixture Note carries two distinct high-entropy markers:

```
body      SS-NOTE-BODY-<32 hex>       at its START and at its END
extract   SS-NOTE-EXTRACT-<32 hex>
```

Two sentinels, because the extract is *allowed* out and the body is not — one sentinel cannot tell
a correct promotion from a leak. The scan matches the **13-character prefix**, so a summariser that
truncates a body to 40 characters still trips it. Start and end, so a head clip or a tail clip is
caught.

**The refusal that matters most: a scan over a population containing zero body sentinels FAILS.**
It does not report clean. This adopts the repository's existing posture — `perf:budgets` exits 3
with *"Refusing to report a measurement of zero"*, `check:contrast` reports unmeasurable surfaces
rather than a pass. A privacy check that passes because it looked at nothing is worse than no
check, because it is recorded as evidence.

The serialised world of **all thirteen scenarios** is scanned, and one note is owned by a different
person entirely so a Project-scoped read that returns it is a visible cross-tenant defect.

```
node --import tsx --test "src/lib/home-layer/fixtures/*.test.ts"
```
