## Session method

Approximately ten consenting adult participants, individually. Explain that this is an interface prototype using invented people and projects, that actions are simulated, and that the interface is being evaluated. Participation is optional and can stop at any time. Use anonymous session IDs P01–P10. Record only task success, confusion and volunteered usability comments; request separate agreement for any recording and do not capture unrelated screens. This is a practical test script, not legal/privacy approval.

Give each scenario one at a time without explaining navigation or naming the control they should use. Ask the participant to say what they expect before acting. A moderator hint makes that journey assisted, not unaided. Do not coach away an audience error. Reset synthetic state between participants, keeping the same final prototype commit.

| Journey | Neutral task prompt | Success and dangerous confusion to observe |
|---|---|---|
| A Project coordination | You need everyone working on the Riverside launch to know the review time changed. Tell them, then leave and return to check it. | Finds correct Project/audience, sends once, distinguishes pending from sent; never assumes another Project or outsider received it. |
| B Private pair | You need to ask one colleague a sensitive planning question. Decide where it belongs and who can read it. | Identifies exactly two-person Project DM and recipient acceptance; no third-party or project-wide privacy assumption. |
| C Outcome | This discussion has led to a job for next Tuesday. Record the work so it can be followed up. | Reviews destination, task title/owner/date and source visibility before confirming; understands date does not automatically publish Timeline. |
| E Recovery | You pressed send and the connection dropped. Find out what happened and finish safely. | Recognizes uncertain state, checks/retries original request, no duplicate success or loss of draft; understands simulated result. |
| F Audience change | Someone left the Project while your message was still a draft. Decide what to do with it. | Notices audience change/read-only/unavailable state and does not assume old audience or automatic send. |
| Private Notes | Keep your own considered note from this exchange. Explain who can find it afterward. | Reviews copied text, recognizes personal Notes ownership and Project filing is not sharing. |
| Attention | A reply is waiting in a thread you have not opened. Find and read that reply. | Locates it without believing that opening parent already read the hidden reply; no sender-visible receipt expectation. |

Run at least one session on a narrow phone view and one keyboard-only journey. Automated keyboard/accessibility checks are separate evidence. Use synthetic state controls outside the task surface to stage failure/consent cases, never ask a participant to interpret an implementation error code.
