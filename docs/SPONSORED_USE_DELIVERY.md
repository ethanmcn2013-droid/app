# Tasks-first sponsored-use delivery

This bounded internal slice captures only deliberate `addTaskAction` calls. Task, activity and specialized delivery intent commit in one SQLite transaction. Current actor task capability, Project archive/deletion and actor/owner account-deletion fences are checked in that transaction. Venue setup still requires the separate core `manageProject` boundary (`2df8cfd6`); integrate this slice on top of that boundary. No template, Notes, Timeline, task completion or automatic action is newly measured.

Capture requires `SPONSOR_USAGE_EVENTS=1`, an App-only `SPONSOR_USAGE_HASH_SALT` of at least16 characters, and exactly one active Project wedding-comp grant backed by a canonical Venue claim. A current Project member with task capability can create under the recipient's gift; the event identifies the acting member while the proof identifies the single Project gift. Overlapping Project grants and historical noncanonical grants suppress measurement without changing task access. Imported, template and automatic task writes do not call this capture path. The salt must be random deployment material; fixtures use synthetic values. No credentials are needed for local acceptance.

The event has exactly seven existing fields: `eventId`, `instrumentationVersion`, `product`, `kind`, `occurredAt`, `subjectIdHash`, `workspaceIdHash`. Its UUID is independent of task identity; time is rounded down to the minute. Hash input is actual Clerk identity and exact Project ID. Raw identities, task content and bearer codes are absent from the transport. The private queue keeps an entitlement reference and an account-erasure hash. Canonical proof separately carries code fingerprint and issuance/interval/epoch identifiers, never bearer code or venue display data.

`POST /api/cron/sponsored-use` requires `CRON_SECRET` and drains at most50 intents using `SPONSOR_USAGE_STUDIO_ORIGIN`. No provider runs inside a database transaction. Unknown/failed delivery remains pending; exact replay dedupes at Studio. Hard raw retention is35 days, including undelivered events; older lost coverage stays missing. Pending erasure controls are retained until acknowledged. Account-to-epoch erasure links expire after24 months. Existing actual account-deletion entry points establish their fence before creating pseudonymous erasure controls; a local failure leaves the fence and prevents later deletion work from starting.

`POST /api/internal/sponsored-use/provenance` authorizes only usage-purpose HMAC requests. Input is `{eventId}` or `{issuanceId,cursor:"0"}`. The latter returns an entire immutable issuance's at-most25 one-use claims in one transaction; larger or ambiguous populations fail, never masquerade as complete pages. It reconciles claimed capacity, including erased consumption receipts, against enumerated grants; any present but unprovable grant or overlapping Project comp grant fails the whole page. It verifies the canonical local receipt/code, exact actor/Project/grant interval, current membership and deletion fences. Each eligible claim includes `measurementAllowed`; an opted-out gift remains in the census as excluded, not silently absent. Event proof requires the acting member and recipient to permit measurement. Optional `SPONSOR_USAGE_PREVIOUS_SALTS_JSON` retains explicit old App-only salts for35-day repair; the receipt keeps its original salt epoch.

`POST /api/settings/sponsor-measurement` with exact JSON `{ "enabled": false }` is the authenticated, same-origin, one-way preference endpoint; GET reads the choice. It calls `optOutOfSponsoredMeasurementAction`. Withdrawal disables only sponsored measurement; it does not revoke the gift, change tasks or alter Project permissions. It queues `{subjectIdHash}` erasure for the actor and `{workspaceIdHash,sponsorId}` erasure for any canonical gift they received, including before a first task event. The latter removes a partner's events under that gift. Usage-private recipient-to-Project hash links carry this erasure after event payloads expire; links age out after24months. Erasure controls survive until Studio acknowledges them, including while capture is off. A workspace erasure tombstone at Studio prevents later replay; this is why the App action does not offer a misleading same-gift re-enable toggle.

Both services need distinct random `SPONSOR_USAGE_SERVICE_SECRET` and `VENUE_ISSUANCE_SECRET`; equal values are refused. Usage HMAC includes purpose `usage.v1`, POST, exact pathname, timestamp, salt epoch and exact body digest. Request size is16KiB and skew is5 minutes. Usage credentials cannot enter issuance. Origins are trusted operator configuration; redirects are refused. No broad App database credential is given to Studio.

Migration `0030_sponsored_use_intents` adds the queue and actor erasure link. Migration `0039_sponsored_measurement_choice` adds the measurement preference and recipient-to-Project erasure link. Apply both before this runtime, including when capture is off: deletion hooks use their tables. The migration tests cover fresh application, no-op and semantic ledger checks. Production migration/deployment remains unauthorized in this task.

Authenticated App report proxy routes are `/api/sponsor-programmes/{programmeId}/reports/{month}` (`format=json|csv|html`) and `/api/sponsor-programmes/{programmeId}/invitations` (GET/POST). They require a Clerk session, internal-test reporting flags and a distinct `SPONSOR_REPORT_ASSERTION_SECRET`; the App mints a five-minute purpose-bound Bearer assertion for Studio. Studio checks the actor's programme capability on every request. The App accepts only a configured Studio origin and exact route, with bounded request/response bodies and no redirects.

The response is streamed with a256-byte bound and a5-second body deadline; extra/duplicate keys, non-JSON, incomplete streams and other2xx responses remain pending. No remote body is logged or persisted. This is defensive transport hardening; no attacker path through the real Studio handler was demonstrated.
