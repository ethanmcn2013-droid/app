# Tasks · Product Excellence Review · 2026-06-09

Caravaggio voice. Execution should be frictionless. The landing page now renders the "done" gesture on the wordmark itself (`tasks` with an animated strikethrough — studio S·70). The product surface has to land that promise. This review names where it does not, in keystrokes and seconds.

---

## 1. Mark-done from the keyboard costs 4 keystrokes when it should cost 1

**Surface.** `src/components/app/board/board-app.tsx:289-293`. Global keyboard handler at lines 264-336.

**Friction.** From an unfocused board, marking a task done requires: locate card visually → click DopamineCheck (1 mouse hop), OR arrow-key to focus the card (1–3 keystrokes depending on starting position) → `Cmd/Ctrl + Enter` (2 more keystrokes, two-handed). Best case keyboard path is 3 keystrokes; typical case is 4. The landing-page gesture strikes through `tasks` in roughly 600ms with zero modifier keys. The real product offers no single-key complete after focus is established.

```ts
if (mod && e.key === "Enter") {
  e.preventDefault(); toggleComplete(id); return;
}
```

There is no `x` or `e` single-key handler. The composer binds `c` (`src/components/app/add-task/add-task-context.tsx:35-42`) — single-key open is already the house pattern. Mark-done is the more common action and got the harder shortcut.

**Cut.** Bind `x` (or `e`, or `Space` if `Enter` keeps its open-detail role) to `toggleComplete` on the focused card in the board's `onKey` handler. Keep `Cmd+Enter` as the alternate. Document the shortcut next to the existing `ShortcutHint` component. Linear, Things, and Superhuman all bind a single key here for the same reason — it is the verb of the product. The wordmark already advertises it.

**Measured payoff.** Single-card complete drops from 3–4 keystrokes to 1. Hand stays on the home row.

**Layer 2 — Recommend.**

## 2. Cross-product "extracted from a note" link is invisible inside Tasks

**Surface.** `src/app/api/notes-extract/route.ts:138-148`; schema column `src/server/db/schema.ts:88` (`sourceNoteId`). No reference to `sourceNoteId` anywhere under `src/components` (verified with grep — zero matches).

**Friction.** When a task arrives via Notes → Tasks extract, the description is hard-coded to the string `"Drafted from a private note in Signal Notes."` (route.ts:142). That sentence is decorative. There is no link back to the originating note. Operator running a venue walks Notes → Tasks → "where did this task come from?" → cannot answer without leaving the product. The schema captures `sourceNoteId` and migration `drizzle/0004_add_source_note_id.sql` is applied. The data is on the row. The surface does not read it. That is friction debt the suite-hardening pass left behind.

The HQ blocker `"Cross-product object links are not yet visible."` is correctly named in `studio/content/hq/products/tasks.md`. The fix is small.

**Cut.** Render a quiet `↩ From Notes` chip in the detail panel header (`src/components/app/detail-panel/panel-header.tsx`) when `task.sourceNoteId` is set. Link target: `https://notes.signalstudio.ie` (suite chrome resolves the user's notebook). Replace the static description string in route.ts:142 with `null` (or empty); the chip carries the provenance. The chip is the gesture; prose is duplicative.

**Layer 2 — Recommend.** Cross-product chrome shape is also Product Experience.

## 3. Two front doors compete for "where do I start" — `/app/inbox` and `/app/my-tasks`

**Surface.** Sidebar `src/components/app/sidebar.tsx:13-17`:

```ts
const NAV_TOP = [
  { href: "/app/inbox", label: "Inbox", icon: "inbox" },
  { href: "/app/my-tasks", label: "My week", icon: "user" },
  { href: undefined, label: "Search", icon: "search" },
];
```

`/app/inbox` (T·N+older — notifications + digest + nudges + weekly snapshot, page.tsx pulls 7 parallel queries) and `/app/my-tasks` (T·82 ships — calm editorial briefing, 5 sections) are two products in the same slot. Both answer "what should I look at first today?" with different metaphors. Inbox is the operational read; My Week is the editorial read. The 80% audience does not arbitrate between two daily-layer reads — they bounce between them, lose the thread, and route the question to their existing notebook.

**Friction.** First-touch tax: a new user sees two top-of-sidebar entries, both promising "your day." That is the §2.2 configuration-tax failure mode dressed as navigation. Every venue operator demoed will ask which one to start in. The answer cannot be "both."

**Cut.** Pick one. My Week (T·82) is the calmer, more brand-coherent read — small-caps section heads, silent on empty sections except Today, no AI-coded nudges. It earns the top slot. Fold Inbox's load-bearing pieces (notification count, overdue roll-forward, weekly snapshot) into the My Week header as quiet rails. Retire `/app/inbox` as a route — 308-redirect to `/app/my-tasks`. The dispatch entry writes itself: `T·NN · cuts · Two front doors collapse into one`.

**Layer 2 — Recommend, with a brief.** Material feature retirement — this is a "material feature addition (subtraction)" in the Layer-2-with-brief sense. Surface to Ethan before cutting Inbox routes; the underlying digest/nudge/snapshot work is load-bearing and needs to migrate, not vanish.

**Friction.** Operators with a mouse will try to click it. It will not respond. The sidebar comment from the same file calls out a different dead affordance already removed (`TEAMS removed 2026-05-19: ... ## 5. The composer's recurrence refusal blocks submit but the user can't tell why

**Surface.** `src/components/app/add-task/quick-create-dialog.tsx:38-44` and `inline-composer.tsx:42`.

```ts
if (recurrenceRefusal) return; // don't create if the recurrence is unsupported
```

**Friction.** When the parser detects a recurrence shape it can't handle, `submit()` silently returns. The refusal banner under the input is informative (amber, 11.5px) but the user pressing `Enter` and seeing nothing happen reads as "the app froze." That is two seconds of confused re-press, then a backspace hunt for the offending word, then a re-submit. The composer is the most-touched surface in the product; a silent no-op here is the worst place for one.

**Cut.** Either (a) submit the task without the recurrence and surface a softer post-create toast (`"Task created. Recurrence skipped — try every Tuesday."`), or (b) keep the refusal but on `Enter`-while-blocked, flash the banner border and shake the input 6px (`x: [-3, 3, -2, 2, 0]` over 220ms) so the system visibly responds to the keystroke. (a) is the frictionless option — the task gets made, the recurrence becomes a follow-up nudge. The product's job is to capture the thought, not to teach the syntax mid-keystroke.

**Layer 2 — Recommend.**

```tsx

 * Shows both hero animations stacked so the operator can evaluate side by side.
 */
export default function HeroCompare() { ... }
```

**Why this fails "should this even exist?"** A two-variant A/B comparison surface for a hero animation has no audience on the production site. It is reachable at `tasks.signalstudio.ie/hero-compare`. The "feat/tasks-hero-v2" branch label rendered in the chrome (line 28) is internal vocabulary on a public URL. The 80% audience will never visit this page; if they do, they read internal scaffolding shipped as a feature. It is the inverse of the brand's discipline-not-feature moat (BRAND.md §2.3): the product surface advertising "we ship things we didn't decide on yet."

**Cut.** Delete the route and the two `TasksHero*` components if no other surface consumes them (verify with grep before delete). If the operator needs the comparison locally, it lives in a Storybook or a notebook, not at a production URL.

**Layer 1 — Decide.** Pure removal.

## Bonus — does the Notes → Tasks → Roadmap chain land?

**Notes → Tasks (extract endpoint).** End-to-end. The route handler at `src/app/api/notes-extract/route.ts` is correctly idempotent (sourceNoteId tuple), workspace-routed (first membership wins), and bearer-secret authed. Migration 0004 is applied. The wire is hot — but as Finding #2 names, the return surface is silent. The hop works, the breadcrumb does not.

**What would break in a real venue's flow.**

1. **A venue operator with zero Tasks workspace.** The endpoint correctly 404s with `"No workspace yet — create one in Tasks before sending extracts"` (route.ts:123). Notes has to surface that string to a non-technical user. If Notes renders the 404 body verbatim, the operator is told to "create a workspace" — vocabulary the brand explicitly retires (BRAND.md §2.2, §3). The endpoint's prose needs to read as venue-operator English: `"Open Signal Tasks once to set up your space, then try again."` That is a Notes-side rendering choice, but the canonical string lives in this repo.

2. **Cross-product hop UI inside Tasks.** No "back to Notes" affordance. Finding #2 above.

3. **Roadmap link.** The blocker `"Cross-product object links not yet visible"` is not just about Notes ↔ Tasks. A task that maps to a roadmap milestone has no chip either. The pattern from Finding #2 generalises — one chip system, two sources (`sourceNoteId`, future `roadmapMilestoneId`), one detail-panel header slot.

**One thing that does land.** The cross-workspace search (`src/components/app/cross-workspace-search.tsx`) and the palette's `Jump to roadmap·/notes·/analytics·` suite hops (`src/components/app/palette/command-palette.tsx:280-330`) are the right shape. Suite chrome at the top is the gesture; per-task chips at the row level are the next layer down. Building chips against an existing palette pattern is days, not weeks.
