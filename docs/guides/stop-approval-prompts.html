Stop the Approval Prompts

Since the design prompt, Claude Code has stopped to ask permission before nearly every command. That setting is read once, when the session starts, so it cannot be changed from inside the session you are in. These steps close it and open a new one with the asking switched off — keeping the conversation you already have.

Where Windows PowerShell Takes two minutes Keeps your current conversation

Why it started asking

Claude Code checks with you before it runs a command, changes a file, or opens a page on the internet. Ordinary conversation never triggers it. Design work triggers it constantly — reading the token file, listing components, running scripts — and every new shape of command counts as a new question.

Clicking don't ask again only covers that one exact command, which is why a long task turns into a long queue of yes/no questions rather than settling down after the first few.

There is a mode that stops the asking outright. Claude Code reads it once, at launch, and never re-reads it — that is the entire reason this is a restart and not a setting you can flip where you are standing.

The steps

Four steps, then two optional ones

What you type sits on a dark background; what you should see back sits on a light one. If the two ever look alike, you are reading the wrong block.

  1. 1

    Leave the session you are stuck in

    In the Claude Code window, type this and press Enter:

    Type this
    /exit
    You should see
    PS C:\Users\you\signal-studio-workspace\app>
the plain PowerShell prompt — Claude Code has closed

    Nothing is lost. The conversation is saved on your machine and you open it again in step 3. If /exit does not respond because something is still running, press Ctrl+C twice instead.

  2. 2

    Check you are in the project folder

    Claude Code remembers conversations per folder, so this has to be right before the next step or you will get a blank session.

    Type this
    cd $HOME\signal-studio-workspace\app
    You should see
    PS C:\Users\you\signal-studio-workspace\app>
no message at all — the prompt line simply now ends in \app>
    If it says Cannot find path

    The folder may still carry its old name from before the repo was renamed. Run dir $HOME\signal-studio-workspace to see what is actually there, and use that name for now — the rename helper in scripts\finish-local-dir-rename.ps1 tidies it up later, and must be run from outside the folder.

  3. 3

    Reopen it with the asking switched off

    This one line does both halves of the job. Type it and press Enter:

    Type this
    claude --continue --dangerously-skip-permissions

    --continue picks your design conversation back up exactly where it stopped. --dangerously-skip-permissions is the part that stops the questions. Starting a clean conversation instead is the same line without --continue.

    You should see
    Claude Code opens with your earlier messages above the prompt,
and a line near the top of the window noting that permission
prompts are bypassed for this session.
    If PowerShell rejects the line

    The flag is two hyphens, then dangerously-skip-permissions, all lowercase, hyphens between every word, on the same line as claude. One letter out and you get an unknown-option message rather than a session.

  4. 4

    Confirm it actually took

    Ask for something small that would normally have stopped to ask. Type this into Claude, not into PowerShell:

    Type this
    list the files in docs/guides
    You should see
    the file list, straight away, with no yes/no question in
between. That gap where the question used to be is the
whole difference.

    If a prompt still appears, the flag did not reach Claude — the table at the bottom of this page names each cause.

  5. 5

    Never type the flag again Optional

    The flag lasts one session. To make it the default everywhere, open your personal settings file:

    Type this
    notepad $HOME\.claude\settings.json

    If Notepad offers to create the file, say yes. Put exactly this in it, then save and close:

    Paste this
    {
  "permissions": {
    "defaultMode": "bypassPermissions"
  }
}
    From then on
    claude
starts with prompts off, in every project, with no flag to remember
    If the file already has text in it

    Do not replace what is there. Add "permissions" as another entry inside the outermost { }, and put a comma at the end of the line before it. A missing or spare comma makes Claude Code ignore the whole file silently, which looks exactly like the setting not working.

  6. 6

    Or stop halfway, if full bypass feels broad Optional

    Bypass covers everything, including commands that delete or overwrite. There is a middle setting that stops asking about file edits — most of your design work — while still checking before it runs a command:

    Type this instead
    claude --continue --permission-mode acceptEdits

    This one you can also reach without restarting: inside a running session, press Shift+Tab to move between the ordinary mode, accept-edits, and plan mode. Full bypass is the only one that needs a fresh start.

What the flag does, and what it leaves alone

  • ✓ It removes the checkpoint, not a limit. Claude could already run every one of those commands; it was asking first. What you give up is the pause before each one — so use it in this project folder, where everything is in git, and not somewhere holding files you could not replace.
  • ✓ It does not sign you in. /design-login still opens a browser and still waits for you there. That is authorisation — a different thing from permission, and no flag skips it.
  • ✓ It ends with the window. Close PowerShell, open a fresh one, type plain claude, and the questions are back — unless you did step 5.

If it still asks

Each row is something you might actually see, and what causes it.

What you see What it means
Still asked after restarting The flag did not reach Claude. Check it sits on the same line as claude, spelled with hyphens throughout and no capitals.
Unknown option, or an unrecognised-argument error Usually a typo. Occasionally a Claude Code too old to have the flag — npm install -g @anthropic-ai/claude-code updates it.
A yes/no about trusting the files in this folder A separate, one-time check the first time Claude Code runs anywhere new. Answer yes once; it does not come back.
A browser window asking you to sign in Authorisation, not permission. Expected during /login and /design-login, and not affected by any of this.
An empty session where your conversation should be You were in a different folder when you ran --continue. Redo step 2, then step 3.
.claude/settings.local.json in your git status Every don't ask again you clicked was written there. It belongs to your machine, not the project; this branch adds it to .gitignore so it stops appearing.

The word in the flag is there on purpose

In a folder of files you could not replace, skipping the checkpoint is a real risk. In this one it is a small, bounded one: the project is in git, so an unwanted change is undone with git restore . and the work you care about is already committed and pushed.

That is the trade being made — a question before every command, in exchange for a session that simply gets on with it. Worth taking here; worth thinking about again anywhere else.
