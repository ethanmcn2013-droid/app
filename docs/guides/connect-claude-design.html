Windows setup · about 15 minutes

Connect Claude Design

Right now your designs live in one app and your code lives in another. These steps join them, so you can pull a design system into the Signal Studio repo and push finished components back — without leaving your terminal.

You need a paid Claude plan You need your own Windows PC Not this web session

Before you start

  • ✓ A paid Claude plan. Pro or Max. A free plan cannot authorise design access, and neither can an API key or a Bedrock or Vertex login — it has to be a Claude subscription you sign into.
  • ✓ Your own computer. This one step genuinely cannot be done from the web version of Claude Code. Signing in opens a browser window, and a web session has no browser of its own to open.
  • ✓ A quarter of an hour. Most of it is waiting for one installation to finish. Nothing here changes your project files.
The steps

Nine steps, in order

Each step shows the exact words to type on a dark background, and what you should see back on a light one. If the two ever look the same, you are reading the wrong block.

  1. 1

    Open PowerShell

    Press the Windows key, type PowerShell, and click Windows PowerShell when it appears. A window opens with a blinking cursor and some text ending in >.

    That window is where every remaining step happens. You type a line, press Enter, and it answers. Nothing you type here can break your computer.

  2. 2

    Check you have Node

    Node is the engine Claude Code runs on. You probably already have it, since this project uses it. Type this and press Enter:

    Type this
    node --version
    You should see
    v24.14.1    ← any number from v20 up is fine
    If instead it says "not recognized"

    Node is not installed. Go to nodejs.org, click the big green LTS button, run the file it downloads and accept every default. Then close PowerShell, open it again, and retry this step.

  3. 3

    Install Claude Code

    This puts Claude Code on your machine. It prints a lot of scrolling text and takes a minute or two — that is normal, let it finish.

    Type this
    npm install -g @anthropic-ai/claude-code

    When the cursor comes back, check which version you got:

    Type this
    claude --version
    You should see
    2.1.234 (Claude Code)
    This number matters

    It must be 2.1.234 or higher. The design commands only exist from that version. If you already had Claude Code and got a lower number, the install command above has just updated it — run the version check again.

  4. 4

    Go to your Signal Studio folder

    All your Signal Studio code lives in one workspace folder called signal-studio-workspace. Go there and look inside:

    Type this
    cd $HOME\signal-studio-workspace
dir
    You should see
    a list of folders — the product code, studio (Signal HQ),
and one or two working copies whose names start with _wt-

    The one you want is the main product folder — the one that is not studio and does not start with _wt-. If it is called app, go in:

    Type this
    cd app
    If it has an older name instead

    The folder was due a rename to app that may never have finished. Just go into it under whatever it is called — cd followed by its name — and carry on; everything works regardless. When you want to tidy it up, close every window using that folder, come back to signal-studio-workspace, and run the repo's own rename helper, swapping in the folder's current name:

    Type this — replace FOLDER with the real name
    powershell -ExecutionPolicy Bypass -File .\FOLDER\scripts\finish-local-dir-rename.ps1

    It refuses to touch anything that is not this project, changes nothing if it fails, and is safe to run twice.

    If signal-studio-workspace itself is missing

    It lives somewhere unusual. Search for signal-studio-workspace in File Explorer, note the folder it sits in, and cd to that full path instead.

  5. 5

    Start Claude Code

    One word, typed from inside the product folder you just entered. The window changes to a welcome screen with a prompt.

    Type this
    claude

    From here you are talking to Claude, not to Windows. Lines beginning with a slash are commands; anything else is treated as a message.

  6. 6

    Sign in to your Claude account

    Type this
    /login

    Your browser opens. Sign in with the account that holds your paid plan, approve the request, then switch back to PowerShell — it will have moved on by itself.

    Use the subscription, not a key

    If you have ever set up an API key on this machine, Claude Code may quietly prefer it, and design access will refuse to work. Signing in here with your subscription is what unlocks the next step.

  7. 7

    Turn on design access

    This is the step everything else has been leading to.

    Type this
    /design-login

    A browser window opens and asks whether to allow access to your design systems. Say yes. Then return to PowerShell.

    You have five minutes

    The window expires after five minutes and you will see a timeout message. Nothing is broken — type /design-login again and finish it more quickly. If no browser opens at all, run it again and choose the manual option, which gives you a code to paste instead.

  8. 8

    Check that it worked

    Do not skip this. It is the difference between being connected and finding out you are not, halfway through some real work. Type this as an ordinary sentence — no slash:

    Type this
    List my Claude Design projects
    You should see
    a list of project names, with who owns each one
    If the list comes back empty

    You are connected, but you have no design system to write to yet. Ask Claude to create one — "create a design system project called Signal Studio" — or make it in Claude Design first, then try the check again.

    If it mentions needing authorisation

    Step 7 did not finish. Go back and run /design-login again, watching for the browser window.

  9. 9

    Start working on your designs

    You are connected. From now on you can stay in this one window. The sync command is:

    Type this
    /design-sync

    Claude compares your local components against the design project and shows you a list of what it wants to change. Nothing is sent until you approve that list. Read it before saying yes — the list is the real record of what will happen, not the description around it.

    You can also just describe what you want in plain English, the same way you would in a chat.

Reference

When something goes wrong

Every message below is one the tool actually produces, with its cause.

What you see What it means
needs design-system authorization Step 7 never completed — or you are in a web session, where it cannot.
Unknown command Your Claude Code predates the feature. Redo step 3 and check the version.
only available with claude.ai authentication You are signed in with an API key, Bedrock or Vertex. Redo step 6.
browser authorization timed out The five minutes ran out. Run /design-login again.
HTTP 403 Your sign-in worked but the account lacks design access. This is a beta feature — check it is switched on for your plan.
An empty project list Connected, but nothing exists yet that you have permission to write to.

One thing worth knowing first

This project has no Storybook, and the sync tool expects either that or a published component package. The 184 files in src/components/ are application screens rather than a tidy library, so pushing all of them would make a mess of your design system.

Start narrow instead: the design tokens in src/ds/, then the basic building blocks in components/primitives/ and components/ui/. Add more once you can see how the first batch lands.

Set in Geist and Geist Mono. Colour, spacing and radii taken from signal-design-system v2.0.1 — the same tokens the product ships. Source lives at docs/guides/connect-claude-design.html; new operator guides start from this file.
