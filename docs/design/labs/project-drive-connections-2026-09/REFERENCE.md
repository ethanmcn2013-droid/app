## What the before proves

1. **The shell is not the problem.** At desktop the numbered Settings rail and
   one main reading column make a stable, understandable frame. A new section
   can feel first-party without inventing new chrome.
2. **Storage speaks in quota, not ownership.** The current adjacent section can
   answer “how much?” but nowhere answers “whose Drive?”, “which folder?” or
   “who can open it?”. Connections must carry those human truths without
   turning into an admin console.
3. **Mobile navigation enters mid-sentence.** The horizontal Settings strip is
   clipped at both sides with no visible start or end. Connections cannot rely
   on its tab label alone to orient a phone user; the page heading must do it.
4. **Resources has earned restraint.** Its uppercase eyebrow, item count,
   compact rows and one intake field should survive. Provenance needs to be a
   quiet row fact, not a second card system.
5. **The empty Resources state is almost invisible.** That is appropriate when
   storage is healthy. The new unavailable and uploading states must grow from
   this line rather than replace it with a setup panel or modal.
6. **No live-access truth exists today.** Membership and Google access are
   different facts. The new screen must visibly say when it last checked
   Google and must surface a removal that has not yet been confirmed.
7. **The current page overuses bordered boxes for adjacent facts.** The usage
   and per-file-limit cards have identical weight despite different
   importance. All three directions must establish one clear ownership fact,
   then let lesser facts recede into rules, rows or a disclosure.

## Reference boundary

These frames record the starting point; they are not a visual specification.
The project brief protects the surrounding shells and the one-control Resources
grammar, not every radius or card inside them. No direction is allowed to hide
storage ownership, infer access from membership, add a second upload control,
or use “Project Drive” as product copy merely because the current screen has no
answer yet.
