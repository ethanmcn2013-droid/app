## What to do

1. Read `refuter-template.md` in this directory for the standard being applied
   and the constraints that are not negotiable.
2. Read the seat JSON you are told to read and take ONLY the finding with the
   id you are given.
3. Verify that specific claim against the real source and the real rendered
   page. Be efficient: check the claim, not the whole design. Keep it to
   about ten tool calls — one read of the source that owns the claim, one
   drive of the page that shows it, and a verdict. You are not re-reviewing
   the design.

## Refute if any of these hold

- it is factually wrong about the frames or the code;
- it is already handled;
- it would violate a non-negotiable constraint (a fourth colour, a third
  weight, a different family, or reopening the locked direction);
- it is taste stated as a defect with no argument;
- the proposed fix would make the work worse, or trade one defect for another;
- it restates something the automated gates already prove.

Confirm only if it is real, specific, and an improvement at a 9.5 bar.

Return a `sharpenedFix` when the finding is real but the fix as written is
imprecise, would break something else, or aims at the wrong file.
