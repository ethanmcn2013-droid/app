FINDING id=the-editor-opens-on-an-empty-band
Seat: Interaction and states
Element: .b-edit { padding-top: 88px } with .b-edit .b-undo[data-empty="true"] { display: flex; visibility: hidden } (b.css lines 815-831)
Problem: Every editor open begins with a hole. Measured at 390x844: the sheet spans y 254-832 and the first thing in it, the "WHAT IT IS" label, sits at 343 — 89px of nothing across the full 366px width, 15% of a 578px sheet on the screen where room is scarcest. At 1440 the same 88px sits at the top of a panel that is otherwise the only thing in a column with 600px of empty below it. The reserve is right — the steppers must not move when the undo bar fills — but the band is spent on nothing, and the panel it heads has no visible name at all: aria-label="Editing Send the invitations" exists for the accessibility tree, and a sighted owner is told which moment they are editing only by reading the value out of the title field. On the phone the sheet covers four other rows' controls, so the panel is most of what is on screen and it opens anonymous.
Proposed fix: Render a sibling of .b-undo inside the same absolute box — "<p class='b-editName'><span class='b-label'>Editing</span> <span class='b-editNameVal'></span></p>" positioned absolute top:16 left:16 right:16 like the bar, the label in the mono micro register at --fore-62 and the value at --size-body --fore — and swap the two by the same data-empty flag: .b-edit[data-undo] .b-editName { visibility: hidden } and .b-edit .b-undo[data-empty='true'] { visibility: hidden } as now, so the band is always occupied and its geometry never changes. Populate it in editor() from nameOf(record) and update it in setTitle() alongside the aria-label it already rewrites, so a rename reaches both. Assert in the gate that at every viewport the topmost visible text inside .b-edit names the moment being edited before any change is made.
