# Isolated typed Ping browser receiving

Run `pnpm test:ping-typed:browser` from the App repository. Uses the installed esbuild (through tsx) and Playwright Chromium; no Next dev server, new dependency, credential or provider request.

The runner mounts the actual TasksProvider, HybridWorkspace and PingTypedPanel. Requests pass through the actual Ping HTTP/session/executor into a disposable synthetic file database. Canonical refresh must hydrate the real provider and appear in its rendered view. Fixture-only boundaries are Next navigation, unrelated server actions, a labelled synthetic Clerk hook/auth adapter and a disabled EventSource. This does not certify genuine Next/Clerk admission.

Six finite cases preserve double Apply, committed response loss and reload recovery, failed refresh with repair, and selection A→B→A during a pending prepare, then add one-target and ten-target typed local-floor observations. Each new trial uses actual Hybrid selection and the mounted panel's restricted `status doing` grammar, one physical executor invocation and its plan-bound receipt read. Literal SQL verifies every selected row, preserved unrelated fields and all unselected rows, including a foreign Project; the persisted receipt and canonical mounted view are checked separately. Output records source inputs, actual execution/receipt counts, cases and desktop/phone captures under a fresh `experience/output/ping-typed/` directory, or `PING_TYPED_BROWSER_OUTPUT`.

Fixture clock for the command service is the current clock; the calendar display is explicitly pinned review context. Audio, provider conformance, hosted receiving, actual-use value and production rollout are separate acceptance work.

The floor state oracle uses `SELECT * ORDER BY id` and the actual driver column names to compare every stored task field. Selected rows may change only the requested lane and the canonical edit `updated_at`, which must equal the committed receipt timestamp; every other field and every unselected/foreign row stays exact. It does not exclude unknown/new columns or hide the real edit timestamp behind a frozen clock.

After the stale-selection case, the fixture privately reads that actual late Prepare response and cancels its known untouched original through the authenticated browser HTTP boundary. It requires the matching `not_invoked` acknowledgement and unchanged execution/receipt totals before starting the floor trials. This is fixture cleanup of a hidden untouched capture, not a panel recovery capability or permission to discard an uncertain invoked original.

`typedFloorObservations` contains one sample for each target count. Counters increment at the actual injected service execute and `getReceiptForCommand` entry points; call attempts are distinct from committed affected/changed counts. Original identities are correlated privately and omitted from the observations. Review and Apply timestamps come from trusted native Playwright mouse-click capture listeners before the React handlers. Ready and confirmed readback timestamps come from the first satisfied browser polling predicates after successful HTTP responses, with enabled/settled controls and every expected canonical row. All timestamps use the same browser performance.now clock rounded down to integer milliseconds. Review-to-ready, Apply-to-confirmed and Review-to-confirmed are separate diagnostics; selection and text entry are excluded, and polling/automation/instrumentation overhead is included. These times do not identify paint or human goal-to-completion.

The current-control comparator remains unavailable: its canonical task/board actions are explicitly throwing fixture adapters. There is no simulated successful bulk-control baseline. Billing, real provider usage and speech end remain null. Two local samples do not establish p50/p95, natural-language fidelity, genuine identity admission, human value, cost, provider comparison or completion of the full typed-floor programme row.
