# Isolated typed Ping browser receiving

Run `pnpm test:ping-typed:browser` from the App repository. Uses the installed esbuild (through tsx) and Playwright Chromium; no Next dev server, new dependency, credential or provider request.

The runner mounts the actual TasksProvider, HybridWorkspace and PingTypedPanel. Requests pass through the actual Ping HTTP/session/executor into a disposable synthetic file database. Canonical refresh must hydrate the real provider and appear in its rendered view. Fixture-only boundaries are Next navigation, unrelated server actions, a labelled synthetic Clerk hook/auth adapter and a disabled EventSource. This does not certify genuine Next/Clerk admission.

Eight finite cases preserve double Apply, committed response loss and reload recovery, failed refresh with repair, and selection A→B→A during a pending prepare, then add one-target and ten-target typed local-floor observations and equivalent existing-control trials. Each Ping trial uses actual Hybrid selection and the mounted panel's restricted `status doing` grammar, one physical executor invocation and its plan-bound receipt read. Literal SQL verifies every selected row, preserved unrelated fields and all unselected rows, including a foreign Project; the persisted receipt and canonical mounted view are checked separately. Output records source inputs, actual execution/receipt counts, cases and desktop/phone captures under a fresh `experience/output/ping-typed/` directory, or `PING_TYPED_BROWSER_OUTPUT`.

Fixture clock for the command service is the current clock; the calendar display is explicitly pinned review context. Audio, provider conformance, hosted receiving, actual-use value and production rollout are separate acceptance work.

The floor state oracle uses `SELECT * ORDER BY id` and the actual driver column names to compare every stored task field. Selected rows may change only the requested lane and the canonical edit `updated_at`, which must equal the committed receipt timestamp; every other field and every unselected/foreign row stays exact. It does not exclude unknown/new columns or hide the real edit timestamp behind a frozen clock.

After the stale-selection case, the fixture privately reads that actual late Prepare response and cancels its known untouched original through the authenticated browser HTTP boundary. It requires the matching `not_invoked` acknowledgement and unchanged execution/receipt totals before starting the floor trials. This is fixture cleanup of a hidden untouched capture, not a panel recovery capability or permission to discard an uncertain invoked original.

`typedFloorObservations` contains one sample for each target count. Counters increment at the actual injected service execute and `getReceiptForCommand` entry points; call attempts are distinct from committed affected/changed counts. Original identities are correlated privately and omitted from the observations. Review and Apply timestamps come from trusted native Playwright mouse-click capture listeners before the React handlers. Ready and confirmed readback timestamps come from the first satisfied browser polling predicates after successful HTTP responses, with enabled/settled controls and every expected canonical row. All timestamps use the same browser performance.now clock rounded down to integer milliseconds. Review-to-ready, Apply-to-confirmed and Review-to-confirmed are separate diagnostics; selection and text entry are excluded, and polling/automation/instrumentation overhead is included. These times do not identify paint or human goal-to-completion.

The existing-control trial uses the mounted BulkBar **Move to → In progress** menu, retaining its concurrent per-task fanout through TasksSurface/HybridStore/TasksProvider. A fixture-only HTTP adapter loads the actual `moveTaskAction` source with the installed TypeScript transpiler, binds DB/auth to the same marked disposable database and synthetic actor, retains actual Project authorization, stored column semantics and `recordActivity`, and returns actual `readCanonicalTasks` rows. Every other action stays throwing. Next cache/events are explicit no-ops; instrumentation receives fixed disabled configuration and its real sink cannot run; there is no ambient database/auth or external network request. Loaded source inputs are fingerprinted in the receipt. This is an explicit canonical-reader boundary rather than a genuine Next server-action transport.

One and ten selected ordinary targets begin with the same task semantics as their Ping counterparts. Each menu gesture causes respectively one or ten actual `moveTaskAction` entries/responses; it causes no Ping executor, receipt read or receipt insertion. The runner awaits every response and the complete canonical Task list in the mounted provider, so optimistic rows or an early intermediate hydration cannot count as confirmation. Literal `SELECT *` verifies all task columns and all foreign/unselected rows. Only the actual action's permitted lane, cleared custom-column/idle fields, destination position and second-resolution update timestamp may differ; the timestamp must lie within that action's entry/completion interval, and position within the independently computed lane-end range. The selected todo→doing transition preserves completion stamps. Each selected task must have exactly its actual scoped Alice move activity. Destination positions can coincide under concurrent fanout; this proof does not invent atomic bulk ordering or correct that behavior.

`currentControlObservations` records the two local samples and links them by target count from `typedFloorObservations`. Menu activation comes from the trusted native browser click on In progress before the React handler; confirmed time comes from the first full canonical mounted-list polling predicate after every successful response. Menu opening, selection and text entry are excluded. Ping Review/Apply and existing Move activation have different interaction shapes; these numbers are local construction diagnostics including automation, polling and instrumentation overhead, not a human value ranking. Billing, real provider usage and speech end remain null. No p50/p95, natural-language fidelity, genuine identity admission, founder accept/reject, provider comparison or full PP-015/PP-033 programme completion follows.
