# Isolated voice-to-Tasks receiving

Run `pnpm test:ping-voice:tasks-browser` after the server/client packet is integrated.

This reuses the actual typed Tasks fixture, providers, Hybrid selection, styles and guarded hydration. Native Chromium fake-device microphone samples travel through the real worklet, PCM encoder, binary HTTP handler, server custody and executor into a disposable proof database. A labelled synthetic 440 Hz WAV provides reproducible nonzero audio. The fixture server supplies synthetic authentication, scripted transcription and an injected proposal; the transcript is not inferred from those bytes.

The ten groups observe literal database state, physical execution/receipt counts, actual uploaded/provider byte equality and the rendered Tasks view. They cover compound edits and a drained partial tail, empty-selection creation, lost Finish response with original receipt recovery and failed refresh repair, stale Begin selection, cancellation during interpretation, new-voice admission refusal while paused, denied typed Apply recovered through acknowledged untouched-original Cancel, native microphone denial, and synthetic storage failures at Start and Finish. The lost-response case pauses new work before original receipt and canonical refresh recovery. Desktop/phone screenshots and scoped accessibility results accompany a source-hashed receipt. No production data, real provider/model requests, genuine Clerk admission, real-user microphone, operational capacity or release acceptance is proved.

The Ping controls are reached through actual Tab/Shift+Tab and activated with Enter/Space for normal voice completion, original-result recovery, typed Review/denied Apply/Cancel, and refusal recovery. Existing Hybrid task-selection helpers set up the fixture; this does not prove the separate roving task-grid selection keyboard contract. Fixed-label focus observations record active element, connection/disabled state and computed outline/shadow before activation and after settlement. A held Cancel response also proves that a user who tabs into the typed input keeps that connected focus. Panels hand off only focus owned by an activated local control, within the same scope/selection, after physical UI work settles; initial mount and reload do not autofocus. Existing visible outlines are retained. Axe and polite status roles are not spoken screen-reader proof.

Manual original-result Refresh uses a held actual HTTP response to distinguish its pending disabled-control state from completion. Reload already supplied the expected canonical rows, so row equality alone cannot prove that this new request settled. The useful-focus assertion runs only after the successful Refresh response, the original Refresh control's removal, enabled Start, confirmed panel status and matching canonical mounted rows. A failed separate receiving attempt that measured BODY during the pending interval remains failure evidence; the new barrier strengthens receiving without changing panel focus behavior or its useful-focus oracle.

Native denial uses a separate installed full Chromium process (`channel: chromium`) without automatic fake-UI permission grant. Context-specific CDP `Browser.setPermission` denial is checked through `navigator.permissions.query`; a recording wrapper delegates to the actual native getUserMedia and observes its `NotAllowedError`. Zero audio upload/provider commit/model/executor/receipt follows, and the original server capture is cancelled with a matching not_invoked acknowledgement. The default headless-shell variant on the inspected Windows runtime returns `NotSupportedError` for this configuration; that failed attempt is retained as a browser-fixture limitation rather than called native permission proof. Controlled microphone samples remain synthetic, with no real-user device claim.

Storage faults are explicitly synthetic, scoped to voice sessionStorage marker writes. Start refusal acquires no microphone and cancels the captured original; a new request identity is allowed only after that original's not_invoked acknowledgement. Finish refusal sends no Finish request/model/execution and releases the UI latch, leaving the same capture available for keyboard Cancel. Committed history and unknown original identities are not cleared merely because storage or transport failed. Actual executor/receipt counts remain three across the complete browser run.

Default product voice remains unavailable without an approved server provider. This fixture never installs its provider or actor into the genuine runtime.

Private command IDs establish that one execution and its lookup refer to the same original; IDs, tokens, transcript and audio are absent from this observation. These are local/scripted call counts, not live provider usage or billable requests.

Confirmed readback timing comes from the first satisfied browser polling predicate for matching canonical rows, confirmed status and settled panel controls, using the same browser performance.now clock rounded down to integer milliseconds. The difference includes browser polling, automation and instrumentation overhead and does not identify paint time. Speech end is unobserved and its timestamp/derived metric are null; billing and real provider usage remain null. Other stages and receipt-read windows are not invented, and strict evaluator output is unavailable because its capture/window authority is not supplied. This single synthetic diagnostic is not model accuracy, live speech latency, a provider comparison, dollar cost or a p50/p95 benchmark.
