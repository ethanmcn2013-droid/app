# Inert Ping input construction

This private packet constructs PP016/017 control flow and PP022 whole-plan evaluation. It introduces no route, provider selection/call, microphone, database access, production migration or automatic retry. It does not pass G1/G2, prove model accuracy or measure live latency. Existing command/executor/fixture semantics remain unchanged. Design/guards are agent recommendations approved under founder delegation, not literal founder design picks.

## Interface and trust boundary

`proposal.ts` parses an application-owned `PingCapture`: generation/connection/context/session IDs, actor, aggregate input-item ID, original command UUID, Project, exact selected IDs, full relevant snapshots, reference instant, Dublin timezone and raw column configuration. It copies and recursively freezes this capture. Exact selected IDs/readsets come from the application; the eventual authenticated runner must capture them from authoritative state and maintain the context key across Project/selection/session changes. Neither the reducer nor a model supplies real session authentication.

Model output is exclusively `ping.proposal.v1` with `outcome:plan` and one operation: `edit_selected` plus effects, or `create_placeholders` plus count/effects/optional literal title. Refusal/clarification has one fixed reason (`unsupported`, `ambiguous`, `incomplete`). Unknown fields, actor, IDs, readsets, finality, additional operations and unsupported effect keys reject the entire proposal. `bindPingProposal` adds captured command/Project/selection/preconditions and runs the accepted core normalizer. Its complete aggregate seal must be supplied by the application after the reducer's completed-input descriptor; it is a control-flow requirement, never a cryptographic/authentication certificate. Schema validity cannot establish fidelity to every natural-language clause.

`createPingInput(capture, monotonicMs)` produces immutable state; `stepPingInput(state, unknownEvent, monotonicMs)` produces immutable next state and **inert descriptors only**. All events contain `generationId`, `connectionEpoch` and `type`. Only state produced by these functions belongs here; provider/model data or deserialized state must never be passed as reducer state. The future runner serializes events and checks current generation/session/context before invoking descriptors, after asynchronous completion and immediately before dispatch. Replay/reload authentication and global multi-tab/device exclusion remain unimplemented.

Descriptors `send_commit`, `flush_tail`, `interpret_once`, `proposed_dispatch` and `read_receipt` are inspectable plans. Emission is not proof of an audio send, billable interpretation, executor invocation, receipt read or committed database effect. No callbacks execute inside these modules.

The factory optionally accepts a copied/frozen application-owned retired generation/epoch allowlist of at most eight distinct dedicated bindings. Only exact known retired pairs are inert; an unexplained generation/epoch fails correlation. This is bounded session metadata from the runner, not a claim that a provider can author its own generation or that reload/session custody is proved.

## Audio metadata, seal and correlation

`accept_audio` contains consecutive `frameOrdinal`, positive even `decodedBytes` and the sole declared format `pcm_s16le_mono_24000`. Exact duplicate frame metadata counts once; differing metadata or holes fail. `encoded_audio` contains `throughFrame` and exact covered decoded bytes. These are normalized **metadata** events; there is no PCM decoder/content verification in this packet. A real capture/encoder adapter must prove actual bytes, no differently encoded duplicate frames, codec and watermark conformance.

`reserve_commit(token)` covers nonempty newly encoded frames in local order. One `send_commit` may await acknowledgement at a time; later reservations queue. This assumes a dedicated connection epoch with no auto-VAD/unrelated item producer. `ack(itemId, previousItemId)` binds the sole pending reservation; the first predecessor must be null and subsequent predecessors must match the prior bound item. Duplicate exact acknowledgements are inert and cannot consume the next reservation. Unsolicited/reused/conflicting identity or predecessor fails correlation. No undocumented echo of a client event ID is assumed.

`delta`/`final` contain `itemId`, `contentIndex:0`, and bounded text. A sole pending commit permits one inert unbound text bucket until matching acknowledgement. It is never current transcript preview or authority before binding. A different pending ID fails. Finals may arrive before acknowledgement or in reverse order; assembly always follows local reservation ordinal with newline separators. Deltas are append-only optional preview, never the final source. Empty/invalid final, conflicting complete text, missing parts or a cap failure rejects the whole input; there is no prefix fallback.

`finish` freezes the accepted frame watermark and emits `flush_tail`. Accepted frames already in that watermark may finish encoding during `sealing`; new audio is forbidden. `seal_tail(throughFrame)` must match the watermark and complete encoding before a nonempty tail is reserved. An empty tail with existing segments adds no phantom commit; wholly empty input rejects. Interpretation requires the full sealed manifest, every acknowledgement and final, and the first Finish. Duplicate Finish cannot extend deadlines or emit another interpretation.

Interpretation descriptor contains the complete ordered text, immutable capture and ordered item manifest. `interpretation(requestId, proposal)` must match the original UUID and sole pending interpretation. Supported valid whole output becomes `ready`; refusal, clarification or malformed output closes without dispatch. `dispatch(currentContextKey)` independently verifies the frozen key and latches dispatch before returning its sole descriptor. Context loss/cancel/disconnect before that step closes; late model results cannot revive it. A new deliberate correction before dispatch starts a new generation; after dispatch the original outcome must reconcile first.

## Outcome certainty, recovery and retention

The interpretation descriptor's separate `modelInput` projection contains only text, selected-task count, reference instant/timezone and supported system-column keys. Capture/session/actor/IDs/readsets/manifest are application-only correlation metadata; the future runner must never forward the whole descriptor to a provider.

Dispatch retains an immutable `{command, context, commandKey}`. `commandKey` is deterministic canonical serialization of both exact payloads: **sensitive internal metadata**, never a log field or provider input, never a cryptographic hash/authentication token. It supports exact inert intent comparisons; future transport must supply real authenticated receipt binding and authorization. The retained command/context contain only the required intended operation/readset. Raw transcript/preview/frame arrays are wiped on dispatch or pre-dispatch closure.

Receipt events must match original command UUID, Project and exact key. Source `executor` represents the one runner's completion. Source `lookup` additionally supplies the issued `windowToken`/`readOrdinal`; unissued current ordinals fail and retired-window results are inert. The event's `committed` label is an injected runner assertion here, not an actual verified receipt. Real receipt schema, fresh current auth, returned payload binding and visible authorized refresh remain later proof gates.

After dispatch, cancellation/disconnect/error/timeout/absent/denied/unavailable **stays unresolved**, preserving original identity and mutation-lane hold. It never implies zero effects or rollback. Confirmation may arrive later and enters `committed`. Current-epoch late audio/text is conservatively an anomaly once text is wiped; exact duplicate versus conflict is deliberately no longer distinguished. It cannot alter intent, add interpretation/dispatch or undo committed truth. This stricter post-dispatch treatment trades duplicate classification for bounded content retention.

Automatic recovery emits at most three read-only descriptors per 10-second window, at offsets 0/500/2000ms when advanced by caller events. `manual_reconcile(actionToken)` can open a later explicit window only after the prior window expires. Tokens must be fresh, never reused; lifetime token storage is bounded to eight windows (including automatic), at most 24 reads in this controller. Lifetime and per-window counts differ. Saturation keeps the lane unresolved for future real recovery support; it does not fabricate a new command or release the lane. Ordinary `reconcile`/`tick` never reset a window. Late-window results cannot consume/confirm a newer window. There is no executor redispatch or model/provider retry.

This controller does not create another generation internally. The eventual runner must enforce one active generation/unresolved command per lane, preserve the exact recovery record, authenticate lookups and define sensitive metadata retention/erasure. Durable browser reload/global account enforcement are not proved here.

## Bounds and deadlines

Approved experiment policy: at most ten selected/created tasks; 1,440,000 decoded mono 24kHz 16-bit PCM bytes (720,000 samples/30s); eight segments; 4,000 assembled Unicode code points including separators; one unbound pending bucket; 512 current-generation pre-dispatch normalized events; one interpretation descriptor and one dispatch descriptor. Arrays reject domain limits before materialization, including sparse huge arrays. Extra/accessor/symbol/exotic record fields fail closed. The 512 input cap cannot block eventual original-ID receipt confirmation after dispatch; post-dispatch data does not create unbounded content storage.

Monotonic fixture deadlines: capture45s; ack5s from its send; Finish→seal/acks/finals10s; interpretation/ready10s from its sole descriptor; executor wait5s→unknown. At-deadline completions reject even before a timer event. Duplicate events never extend deadlines. These are delegated guard choices, not latency targets; real transport cancellation/deadline conformance remains open.

## Whole-plan evaluator and checks

`evaluatePingWholePlan` requires a separately supplied independent fixture/human whole-plan label. It canonicalizes both entire proposals under the same capture and compares all effects/count/title or complete refusal/clarification. A supported prefix cannot match an independently labelled unsupported mixed instruction. Calling a label independent cannot prove its independence: holdout custody and real interpreter observations remain external acceptance responsibilities.

Observation counters are actual/simulated external observations, distinct from reducer descriptor counts: interpretation calls, executor calls, lifetime receipt reads plus per-window records, known committed-effect count and client knowledge. Unknown dispatched outcome requires `observedCommittedEffects:null`; private-store fixtures must keep their separate omniscient effects evidence outside that client-knowledge record. A receipt/visible-state assertion is not generated by the evaluator.

Timing source is explicitly synthetic or measured. Missing authorized visible readback gives null completion timings. Capture-ready→visible, speech-end→visible and Finish→visible are separate metrics; synthetic stage durations are never live latency or a production benchmark. Ordering, duplicates, unknown stage names and inconsistent counters reject. The evaluator performs no model calls, labels instruction semantics automatically or invents accuracy.

`pnpm test:ping-input` runs the owning pure corpus; the normal blocking test script also calls it. `pnpm test:ping` preserves the separately accepted 23 executor/contract checks. Further acceptance needs immutable independent input corpus review, receiving checks, actual provider/session/runner conformance, paired typed/control evaluation, then founder/external/privacy/operating gates. A construction packet alone cannot close those gates.
