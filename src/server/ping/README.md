# Disposable Ping executor proof

This is a private, injected P1 construction proof. It adds no App route, provider request, microphone UI, production migration or environment-selected database. It does not establish a release or readiness gate.

The pure versioned contract is `src/lib/ping/command.ts`. `createPingCommandService` accepts the existing transaction adapter and a trusted `PingExecutionContext` captured outside model output. Actor, Project, exact selected IDs, input item identity/completion, reference instant, timezone, raw column configuration and relevant task read set are bound before execution. A normalized command cannot supply actor/finality, arbitrary patches, generated IDs, sequence allocation, additional operations or a partial destructive clause. The future transport must derive actor from real session auth and maintain the capture generation; this factory does not authenticate a browser request by itself.

Supported proof operations are exact selected-task self assignment/removal, explicit due-date set/clear, configured system-column status set, and creation of 1–10 placeholders with default `Untitled task` or one literal shared title. Selected tasks must be top-level, unarchived, non-recurring, non-milestone and have no custom-column claim. Only `Europe/Dublin` and four system keys are accepted. Full V1 custom columns, user timezones, broader structural tasks and voice/provider behavior remain separately unresolved.

Authorization is fresh and membership-rooted, permits only canonical owner/member roles, uses canonical capability rules, and checks actor/primary owner account deletion plus Project deletion fences in the same transaction. Archived Projects deny new writes; still-authorized members may recover historical receipts. Semantic preconditions compare touched assignment/status/date fields and dependent completion/scheduling fields, without pretending the existing second-resolution timestamp is a universal revision.

All selected preconditions pass before any effect. Creation reuses `prepareCanonicalTaskCreate` and `createTaskInTransaction`, allocates current sequence/position inside the transaction, writes canonical task-add activity, and calls real sponsored-use capture with explicit configuration. Enabled synthetic canonical issuance/grant fixtures prove intents/subjects roll back together. Selected updates write logical-field activity in the same transaction; they do not claim full existing server-action notifications, cache invalidation, recurrence, export/erasure or broader update parity.

Dates write both `due` and `due_at` using the existing 09:00 UTC proof convention. Tests exercise the actual Hybrid reader at Dublin spring/autumn DST and clear. Existing `start_day`/`duration_days` remain unchanged: clearing the due anchor can leave an independently Planning-Period-anchored range visible. The receipt reports changed fields, not a promise that every schedule representation became unscheduled. A general timezone and scheduling policy still requires review.

The actor-scoped command receipt and immutable payload/context hash commit with task/activity/capture effects. Repeated identity/hash returns the original receipt; changed payload conflicts. Recovery first performs an authorized read transaction, avoiding a writer lock for an already committed result. If absent, the writer transaction repeats receipt lookup and all write authority checks to close races. `affectedCount` includes selected no-ops; `changedCount` reflects actual changed tasks. Generic failure results do not serialize SQL/driver errors containing private bound text.

Run `pnpm test:ping` (also the first blocking step of `pnpm test`) and `pnpm typecheck`. The disposable process worker lives at `scripts/ping/proof-contention-worker.ts`; its synthetic CLI diagnostics are outside product server source. The corpus uses new temporary `signal-ping-proof-*` directories containing only synthetic file-backed SQLite databases, canonical migrations 0014 onward, foreign keys enabled, and a fixture-only receipt table. It proves literal state, rollback at task/activity/capture/receipt seams including insert six, selected compound rollback, replay/reconnect, current receipt authority, stale context and configured completion semantics.

## Installed local-driver contention limit

The canonical local adapter owns one queue and one connection. Deliberately using two independent file connections exposed installed libSQL 0.17.3 `SQLITE_BUSY` on Windows: contention failed closed, but the same process retained blocked writer state even after handles were closed/reopened. The test records the actual recovery outcomes on each platform, accepting either exact authorized replay/new write or temporary unavailability with no duplicate committed state; it does not require the Windows defect on platforms that recover. It then proves durable receipt/current authorization and new writes from a fresh worker process after the original process exits, accounting for any earlier successful new write. Read-only receipt recovery avoids acquiring a new writer lock, but a poisoned adapter is not generally retryable. Adapter retirement/recreation and remote interactive concurrency remain P2 work; this packet proves no cross-process throughput or hosted capacity.

Every fixture/worker closes its clients in `finally`. Recovery resolves the real target under the real operating-system temp root, requires an immediate `signal-ping-proof-*` parent and `synthetic.db` filename, then reads a fixture-only version marker before any service or membership mutation. Non-fixture/escaped paths are refused before opening the database. This marker is an isolation guard, not product authorization. Temporary databases remain as synthetic diagnostic artifacts. Cleanup may remove only individually verified temporary directories whose resolved paths stay under the operating-system temp directory and whose leaf starts `signal-ping-proof-`; never enumerate/delete application data or copy customer `.env` files.
